# team/ — who is building it

| File | What it is |
|---|---|
| `TEAM.md` | Roster, activation status, escalation path — start here for who's who. |
| `team-principal.md` | Coordinates cycles, owns `STATE.md`/`NATHAN-STATUS.md`, dispatches work. |
| `product-owner.md` | Owns `product/BACKLOG.md` and `product/CONCEPT.md`. |
| `designer.md` | Owns `product/LAYOUT.md`, the `design/` SVG mirror, screen specs. |
| `art-director.md` | Owns `product/BRAND.md` and `product/brand/`. |
| `mobile-dev.md` | Builds the app UI and native pipeline (`app/src/ui`, builds/runbooks). |
| `backend-dev.md` | Builds storage, the store, and data plumbing (`app/src/storage`, `app/src/store`). |
| `navigation-engineer.md` | Owns the live engine and route/gate logic (`app/src/live`, `app/core`). |
| `race-engineer.md` | Timing/scoring semantics and live-screen behaviour while riding (`app/src/live`, red-light rules). |
| `qa.md` | Test coverage and verification discipline. |
| `librarian.md` | Repo hygiene, archival, file discipline. |

Read by: each role reads its own file plus `TEAM.md`; the Team Principal reads all of
them when planning a cycle.
