# app/tests — headless QA suite

Run: `node --experimental-strip-types app/tests/run.ts` (Node >= 22.6, zero deps; MODULE_TYPELESS warning is harmless). Prints PASS/FAIL/SKIP per test, exits nonzero on FAIL. 2026-08-16: **82 tests, 79 pass / 0 fail / 3 skip** (was 63/60 before the store suite) (skips = python-oracle checks on fixtures that have no python rows by construction).

**Fixtures** (`fixtures/`, ~370 KB, committed; JSON fixtures rebuilt with `build_fixtures.ts` against `data/`):
clean ride per track (full-res, python-parity-anchored) · 237s-gap ride `20260521-1056` (D-016(a) time-aware re-acq, incl. no-reacq counterfactual) · late-lock `20260805-1034` (D-016(b) START skip) · real detour (D-015) · wrong-direction (Morning ride vs EveningA detector) · synthetic mid-ride kill (truncated between G2/G3) · synthetic first-ever ride (no benchmark history). Each embeds engine snapshots + (where real) cycle-004 python parity rows as an independent oracle.
**`qualifire-20260815-0024.gpx`** — the first GPX the real app ever exported (acceptance night, 2026-08-15 00:24): a **~94 s stationary doorstep test loop, NOT a commute** (92 points, ~20 m span). Exported by the pre-F-2 build, so its 17-point scrambled block is committed evidence of the on-device append race; never regenerate it.

**Engine suite** (`engine_suite.ts`): offline sector times/flags and live gate sequences vs snapshots and python rows; invariants (monotonic chainage, in-order single fires); semantic checks per failure case above.

**Storage suite** (`storage_suite.ts`, via `core.ts` + memory adapter only): JSONL encode→decode bit-exact identity; GPX export→core-parse round trip preserving every fix time/coord on a real 907-fix ride; torn-tail recovery at every possible cut point; crash-restart resume + endRide idempotence; index.json rebuild; appendFix guards; **F-2 regression locks** — a jittered concurrent append burst racing the crash-recovery read-back branch must keep file order == call order with the end record last (the harness first proves the same jitter scrambles the pre-fix unserialized pattern), and a deliberately scrambled-on-disk ride must export chronologically without the JSONL being rewritten (D-023); the real 0024 export must parse 92/92 with core's parser and re-export chronologically.

**Live suite** (`live_suite.ts`): drives `app/src/live/engine.ts` — the exact class the phone feeds — over the fixtures. Route auto-lock picks the right track on all three clean rides, locking within the documented bounds (~400 m advance, ≥200 m margin, and within ~400 m of the Evening A/B split freeze); displayed sector + lap times equal the offline parity pipeline at 1e-6 s (partial-buffer relaunch at 5e-3); honesty rules locked: estimated ⇒ ~raw only, no moving/stopped time; skipped/offroute ⇒ missed; dirty sectors ⇒ estimated lap; late-lock ⇒ no lap raw; mid-ride kill ⇒ no lap, S3 current; the real stationary 0024 export locks nothing and fires nothing. Note: engine.ts/refs.ts use Metro-style import specifiers (extensionless + bare .json), which plain Node cannot resolve — the suite shims resolution via `module.registerHooks` (Node ≥ 22.15) with app code byte-untouched. Flagged to Mobile Dev: normalizing those two files to the repo's `.ts`-extension convention would retire the shim.

**Store suite** (`store_suite.ts`, cycle-008 build): drives `app/src/store/` — the catalog (landmarks · ways · routes · versioned gate sets) and the derived results store, both pure and fixture-free. Locks the structural failures the archive actually produced: overlapping landmark discs are an ERROR (the 88-visit cluster merged two real places 141 m apart), loops need a discriminator, gate chainage must strictly increase, dormant landmarks seed history but are never offered at START, and a *middle*-gate move keeps laps comparable while an end move (IDEAS §22) breaks them. On the results side: the index is a rebuildable cache, `derivedBy` mismatch marks a result stale rather than patching it, D-028 ranking holds (estimated never ranks even when quickest raw, tripwire-demoted seeds unranked, archive laps ranked as ghosts, no fake position label), dirty sectors never reach a benchmark, and **one stored history feeds both the rolling-day and last-N windows with no tier or colour anywhere in the store** — the property that lets the store exist before the IDEAS §19 colour ruling.

Also covers `src/store/derive.ts` against the real fixtures: a clean ride derives sector-for-sector equal to the offline parity pipeline (1e-6 s), and the seeded catalog (`src/store/catalog.seed.json` — the six ratified landmarks + D-016 gates) validates with no overlapping discs.

**F-3 (design finding, cycle-008 build): offline cannot produce "estimated".** A GPS gap does not yield an interpolated sector offline — the projector's ~240 m forward search window cannot skip the hole, so fixes after it project badly and core flags the sector `excluded_offroute`. Punching a synthetic 90 s hole into `clean_morning` reproduces it exactly, and the real 237 s-gap ride behaves the same way. `estimated` is therefore a LIVE concept (a gate fired under D-016(a) re-acquisition) and reaches `deriveRideResult` only when the caller passes those sector indexes in; the derive step never infers it. Both paths refuse to colour or rank the sector, so the honesty rules hold either way — but the offline verdict is `missed`, not `estimated`, and a first attempt that assumed otherwise failed the suite.

**Findings** (both fixed in storage, regression-locked here): **F-1** — appending after a mid-write kill glued the new record onto the torn last line; storage now heals the missing trailing `\n` first. **F-2** — concurrent appendFix bursts after a mid-ride JS relaunch raced the read-back branch and landed in promise-resolution order (real ride `20260815-0024`, 17-line scrambled block); storage now chains appends per ride and gpxExport stable-sorts by `tUnixMs`.
