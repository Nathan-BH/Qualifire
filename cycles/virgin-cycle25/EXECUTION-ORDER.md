## Pipeline per brief

Execute (Sonnet, `EXECUTOR-RULES.md`) → Inspect (fresh-context Opus, `INSPECTOR-RULES.md`) → coordinator fixes trivial findings (< ~10 mechanical lines) or forwards anything else to a fresh Fable → next brief. Do not start brief N+1 before brief N's Inspect is PASS (or PASS WITH NOTES the coordinator accepts). The coordinator — never the executor — updates STATE.md / OPEN-ITEMS.md (each brief's §7 paragraph) and commits (one commit per inspected brief, or one at the end; the tree is otherwise uncommitted between briefs).

Tiers: Digest = Haiku (done: 01/02 digests). Plan = Fable (this folder's briefs; also any escalation ruling). Execute = Sonnet. Inspect = Opus, fresh context, never the executor's session. Coordinator = the chat model (narrates every dispatch: tier, model, one-line mandate; ends with the tier | model | tokens | outcome table).

## Escalations (Nathan is asleep — nobody rules by chat)

- An executor that hits an anchor mismatch, an unanticipated test failure, an UNLISTED/STALE string outside the brief's table, or any call the brief did not make: STOPS, writes the stop verbatim to `cycles/virgin-cycle25/ESCALATIONS.md` (heading `## brief-NN / <date time>`; what it expected, what it found, the command and its output), reports, ends. It never guesses, never rules, never edits around it.
- The coordinator forwards the escalation VERBATIM (the ESCALATIONS.md section) to a fresh Fable Plan subagent, which answers in the same file under `### Ruling` (and amends the brief if needed), then the coordinator re-dispatches the executor on the amended brief. If the coordinator runs on Sonnet it never rules itself (CLAUDE.md 2).
- An Inspect FAIL is handled the same way: trivial (< ~10 mechanical lines, no design content) → coordinator fixes directly and reruns the two checks; anything else → fresh Fable.
- Nothing is committed while an escalation is open.
